# dev: исходники, сборка и тесты

Каталог для разработчика. Страницу, которую открывают сотрудники, составляют только файлы в корне репозитория (`index.html`, `sw.js`, …); каталог `dev/` на работу сайта не влияет.

## Что здесь

| Путь | Назначение |
|---|---|
| `src/` | исходники приложения (порядок склейки — `src/manifest.txt`) |
| `assemble.py`, `build.py` | сборка: `python3 build.py --demo` — тестовая сборка для регрессии (`out/КБЖУ_калькулятор_автономный.html`); `python3 build.py --test` — сборка с отдельным хранилищем и заблокированным рабочим адресом (`out/Не_на_глазок_ТЕСТ.html`); флаг `--strip-prices` убирает цены и цены продажи |
| `sync/gasmock.js`, `sync/gasserver.js` | имитация Apps Script и HTTP-обёртка для браузерных тестов |
| `sync/mk_test_script.js` | готовит скрипт и учётные записи для отдельной тестовой таблицы |
| `sync/Code.gs` | копия `../sync/Code.gs`, делается автоматически (`runreg.sh`) |
| `*.js` (`pw*.js`, `t_*.js`, `sync/t_gas_*.js`) | тесты; перечень — `tests.list` |
| `tools/mkfont.py` | подмножество шрифта для PDF (нужен только для пересборки шрифта; требует `fontTools` и исходный шрифт Liberation Sans) |
| `acceptance/index.html` | страница автоматической приёмки на настоящем Google-скрипте |
| `ACCEPTANCE.md` | порядок приёмки на настоящем сервисе |
| `RESULTS.md` | результат последнего полного прогона |

В репозитории нет рабочих данных: нет базы сырья с ценами (`live/`), нет адреса и кодов рабочего скрипта, нет файлов ТТК и прайсов. Тесты используют только синтетические данные («ТЕСТ …») и придуманные коды вида `adm-5678`.

## Требования

Python 3 (с `fontTools` для PDF-шрифта не нужен: подмножество шрифта уже в `src/`), Node.js 18+ и Playwright с Chromium. Пути берутся из переменных окружения:

```
export PW_MODULE=/путь/к/node_modules/playwright   # если playwright не виден через require
export PW_CHROMIUM=/путь/к/chromium                # если Chromium не найден автоматически
```

Для теста PDF нужен `pdftotext` (poppler-utils).

## Запуск

```
cd dev
./runreg.sh | tee out/reg.log        # сборка и полный перечень из tests.list
node -r ./pwpatch.js pwfc7.js        # один тест (после python3 build.py --demo)
node sync/t_gas_fc.js                # серверные тесты на имитации Apps Script, без браузера
```

Строка `имя rc=0 …` — тест пройден. Подробный вывод — в `out/reg/<имя>.log`.

Тест `pwcompat90.js` берёт страницу приложения 90: `git show 5392f60:index.html > out/app90.html` (`runreg.sh` делает это сам, если рядом есть git-репозиторий).

## Что не вошло и почему

Часть прежних тестов опирается на рабочие файлы (ТТК, прайсы, выгрузки) и на встроенную базу сырья. Их нет в репозитории: они перечислены в `tests.excluded.txt` с причиной. Эти сценарии проверяются у владельца на рабочих файлах.

## Тестовая сборка и рабочая база

`build.py --test` не вшивает адрес скрипта и работает со своим хранилищем (ключи с префиксом `T~`), поэтому данные рабочей страницы не затрагиваются. Блокировка рабочего адреса включается, когда при сборке рядом лежит `sync/script_url.txt` с рабочим адресом: тогда его идентификатор попадает в сборку и запросы к нему отклоняются. В репозитории этого файла нет (рабочий адрес в нём не хранится), поэтому сборка из репозитория блокировки не содержит: тестовую сборку для приёмки собирает владелец рабочего адреса, либо вы сами следите, чтобы вводился только адрес тестового скрипта (см. `ACCEPTANCE.md`).

Для страницы по ссылке: `python3 build.py --test --strip-prices --test-url=https://script.google.com/macros/s/…/exec` вшивает адрес именно **тестового** скрипта (сборка остановится, если адрес совпадает с рабочим из `sync/script_url.txt`, когда этот файл лежит рядом). Цены из встроенной базы убираются (`--strip-prices`). Результат — `out/Не_на_глазок_ТЕСТ.html`; его кладут как `index.html` в отдельный репозиторий для Pages.

## Тесты расчёта фудкоста

`pwfc9.js` воспроизводит четыре замечания независимой проверки (баланс факта с перемещениями и возвратами, цена закупки без суммы, литры без плотности, кеш названий блюд). `pwfc10.js` проверяет их влияние на рекомендации, потенциальную экономию и выгрузки плана (Word, Excel, PDF).
